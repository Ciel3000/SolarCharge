# Plan: Fix PayPal Subscription Flow

## Problem
- Subscriptions not created in production database
- Sandbox works (logs payment)
- No webhook - client-side payment verification only

## Root Causes Identified
1. No server-side webhook from PayPal - relies on frontend callback
2. No payment record created in `payment` table
3. Missing PRODUCTION PayPal client ID (falls back to sandbox)
4. No server verification that payment actually succeeded

## Solution Plan

### Step 1: Verify PayPal Client ID Configuration
- Check frontend/.env or environment variables
- Ensure `REACT_APP_PAYPAL_CLIENT_ID` is set to PRODUCTION client ID
- Check `SubscriptionPage.js` line 12 - should NOT default to 'sb'

### Step 2: Add Server-Side Payment Verification (Recommended Fix)
Instead of trusting frontend, verify payment server-side:

1. **Read PayPal capture from frontend** - The frontend receives `orderID` after PayPal capture
2. **Verify with PayPal API on server** - Call PayPal's Get Order API to verify payment succeeded
3. **Create payment record** - Insert into `payment` table
4. **Create subscription** - Then insert into `user_subscription` table

Changes needed in `server.js` at `/api/subscription/create`:
- Accept `orderID` from frontend
- Call PayPal API to verify payment status is "COMPLETED"
- Only create subscription if verified

### Step 3: Add Payment Record Creation
- Insert into `payment` table when creating subscription

## Files to Modify
- `backend-server/server.js` - `/api/subscription/create` endpoint
- `frontend/src/pages/SubscriptionPage.js` - send orderID to backend

## Priority
1. Fix step 1 first (check env var) - simplest fix if using sandbox
2. Implement step 2 for proper production solution
